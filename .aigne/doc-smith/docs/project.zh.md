## 获取帮助

如果你需要帮助，Tokio 社区非常活跃并乐于提供协助。在提问前，建议先查阅官方[指南](https://tokio.rs/tokio/tutorial)和 [API 文档](https://docs.rs/tokio/latest/tokio)。如果仍未找到答案，你可以通过以下几种方式与我们联系：

- **Discord：** 如需实时聊天和提问，请加入我们活跃的 [Tokio Discord 服务器](https://discord.gg/tokio)社区。
- **GitHub Discussions：** 如有问题、想法和长篇讨论，请访问[讨论页面](https://github.com/tokio-rs/tokio/discussions)。

## 参与贡献

我们很高兴你能帮助改进项目！欢迎所有人参与贡献。在开始之前，请阅读我们的[贡献指南](https://github.com/tokio-rs/tokio/blob/master/CONTRIBUTING.md)，其中提供了参与所需的所有信息。

除非你另有明确声明，否则你有意提交以包含在 Tokio 中的任何贡献，都将根据 MIT 许可进行授权，不附带任何附加条款或条件。

## 相关项目

Tokio 项目还维护了其他几个高质量的库，它们是 Rust 异步生态系统的基石：

*   **`axum`**：一个注重易用性和模块化的 Web 应用程序框架。
*   **`hyper`**：一个快速且正确的 Rust HTTP/1.1 和 HTTP/2 实现。
*   **`tonic`**：一个基于 HTTP/2 的 gRPC 实现，专注于高性能、互操作性和灵活性。
*   **`tower`**：一个用于构建健壮网络客户端和服务器的模块化、可复用组件库。
*   **`tracing`**：一个用于应用程序级追踪和异步感知诊断的框架。
*   **`mio`**：一个对操作系统 I/O API 的底层、跨平台抽象，为 `tokio` 提供支持。
*   **`bytes`**：用于处理字节的实用工具，包括高效的字节缓冲区。
*   **`loom`**：一个用于并发 Rust 代码的测试工具。
